# v1.2.0 (2026-08-XX)

- Added a easy to use target visibility notebook ("target_visibility.ipynb") which can accept multiple targets including just names of targets.
    - The target visibility notebook accepts planet names ending in a lowercase letter ("TRAPPIST-1 b", "WASP-160 B b"). Their ephemerides are pulled from the NASA Exoplanet Archive, and transits (blue) and secondary eclipses (purple) are overlaid on the visibility timeline with the observable fraction of each event reported. Unresolvable stars, unknown planets and non-transiting planets each raise a warning and degrade gracefully.
- `get_all_constraints`, `get_constraint`, `get_separations`, `get_star_tracker_constraint` and `summary` now run off the same precomputed data as `get_visibility` instead of doing their own per-body ephemeris and coordinate transforms.
- Fixed the diagnostic API disagreeing with `get_visibility`. It used astropy's `separation`/`AltAz` while `get_visibility` used direct vectors, so a step could be reported not visible with no constraint failing. Note that `get_separations["earthlimb"]` was an AltAz altitude, referenced to the geodetic horizon, added to a geocentric limb half-angle; it is now geocentric throughout, which shifts reported limb angles by up to 0.1 deg and matches the value the constraint is actually applied to.
- `get_visibility_best_roll` is much faster. The orbit sampling grids and their ephemeris are now built in one vectorized pass instead of two astropy calls per orbit, cached and shared between every target on the same time grid; the roll sweep runs over all roll angles at once; and the per-orbit target transform is done once for all orbits. Visibility, roll and star tracker results are unchanged. Measured on 5 targets over 14 days at 10 minute cadence: 87 s to 9.5 s.
- Added the `ephemeris_step` option to `Visibility` (default None, i.e. unchanged behavior). Set it to a time Quantity (e.g. `60*u.min`) and the Sun and Moon are evaluated on a grid of that spacing and interpolated, taking the same 5-target run to 2.4 s. Only the smooth geocentric body motion is interpolated, the spacecraft's own position is always exact, so directions stay accurate to better than 0.01 deg.
- Fixed the `_precompute` cache keying on `id(time)`, which could serve another time grid's data if a recycled object address happened to match.
- Added `use_dynamic_earthlimb` (default False) to `Visibility`. When True the boresight Earth limb keep-out follows the piecewise DPC wedge curve as a function of the Earth illumination angle at the nearest limb point, instead of the fixed day/night limb limits. Star tracker keep-outs are unaffected.
- **Changed the default `daynight_mode` from `"subsatellite"` to `"limb"`.** This changes results for any run that sets `earthlimb_day_min` or `earthlimb_night_min` without naming a mode. The day/night split models stray light from the sunlit Earth, which comes from the patch of Earth the boresight grazes rather than the ground beneath the spacecraft — and `"limb"` is what `use_dynamic_earthlimb` already measures, so the two Earth limb models now agree. Because an observable target is anti-sunward (`sun_min` ≥ 91 deg), the limb toward it is systematically darker than the subsatellite point: 97% of the disagreements between the two modes are cases where `"subsatellite"` says day and `"limb"` says night, so the new default is uniformly more permissive, never less.
- Fixed `summary()` reporting the wrong Earth limb threshold. It derived day/night from the nearest limb point regardless of `daynight_mode`, so in `"subsatellite"` mode it could print the night limit and `[night]` while `get_visibility` had applied the day limit — a line such as `req: 5.0 deg [night], actual: 39.7 deg` next to a FAIL. Only the printed diagnostic was affected; visibility results were always correct.
- Added `get_star_tracker_breakdown`, which reports which star tracker fails which keep-out per timestep, with the separations and limits behind each. It shares its geometry with the constraint check itself, so the per-check masks always reconstruct the verdict.
